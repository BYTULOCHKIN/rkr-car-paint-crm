# Перегляд замовлень і переходи статусів для виконавця

Тип: AFK. User stories: 21–26, 29–30.
PRD: [Команда, ролі та виконавець замовлення](../team-roles-and-order-assignee.prd.md).

## What to build

Виконавець бачить усі замовлення своєї автомалярки, включно із призначеними
іншим людям. Може читати опис, роботи, кількість, ціни, суму, дати, схему
кузова та історію, але не редагувати ці дані. Є проста дія лише наступного
статусу: «У роботі → Готово → Видано». Кожна дія зберігає потрібну фактичну
дату й подію в історії.

Це завершений робочий шлях співробітника: відкрити замовлення → ознайомитися
з роботами → відмітити готовність → відмітити видачу. Адміністратор зберігає
можливість виправляти дані й повертати статус назад за поточними правилами CRM.

## Acceptance criteria

- [ ] Виконавець бачить усі замовлення лише поточної автомалярки; призначення іншому учаснику не приховує замовлення й не забороняє допустимий перехід статусу.
- [ ] Опис, роботи, кількість, ціни, сума, схема кузова та призначення доступні для читання, без форм редагування для виконавця.
- [ ] Виконавець не може створювати або редагувати клієнтів, автомобілі, заявки чи вміст замовлень; прямі серверні запити також відхиляються.
- [ ] Для «У роботі» доступний лише перехід у «Готово», для «Готово» — лише у «Видано», для «Видано» наступної дії немає.
- [ ] Сервер відхиляє пропуск кроку, повернення назад, зміну плану, редагування вже записаних фактичних дат, цін або виконавця.
- [ ] Фактична дата готовності чи видачі визначається на сервері за київською датою; наявні фактичні дати та план зберігаються.
- [ ] Для старого замовлення без потрібних попередніх фактичних дат UI пояснює необхідність адміністративного виправлення; виконавець або міграція не вигадують ці дати.
- [ ] Статус та історія зберігаються атомарно. Порожня або невдала дія не створює фіктивної події.
- [ ] Застарілий статус або ревізія відхиляються зі зрозумілим повідомленням; повторне натискання під час збереження заблоковане.
- [ ] Якщо задача №4 вже реалізована, подія переходу містить автора за її контрактом; в іншому разі перехід сумісний із подальшим додаванням автора без окремого механізму журналу.
- [ ] Адміністратор зберігає чинні можливості виправлення дат і повернення статусу з обов’язковою причиною там, де вона вже потрібна.
- [ ] Інтерфейс виконавця читабельний на телефоні й комп’ютері, з доступними підписами дій та індикатором збереження.
- [ ] Тести перевіряють повний послідовний шлях, доступ до чужого призначення всередині своєї організації, відмову для чужої організації, підроблені запити, конфлікти й незмінність цін та плану.
