# Перепризначення виконавця та історія

Тип: AFK. User stories: 14, 17–20, 27.
PRD: [Команда, ролі та виконавець замовлення](../team-roles-and-order-assignee.prd.md).

## What to build

Адміністратор може змінити виконавця наявного замовлення або вручну призначити
його старому замовленню. Після збереження поточні відображення й друк показують
нового виконавця, а історія зберігає «Було / Стало». Нові записи історії
ідентифікують користувача, який виконав дію, щоб відрізняти дії членів команди.

Це завершений шлях: відкрити замовлення → перепризначити → зберегти → побачити
нове призначення та історичний запис. Видалення співробітника з Clerk не
стирає його історичного імені й не спричиняє автоматичного перепризначення.

## Acceptance criteria

- [x] Змінити виконавця може лише адміністратор; сервер відхиляє прямий виклик від виконавця.
- [x] Для нового призначення діють ті самі перевірки активного членства й організації, що й при створенні замовлення.
- [x] Старе замовлення без призначення можна призначити вручну; відсутність історичного виконавця не блокує читання, друк чи інші адміністративні правки.
- [x] Видалений із команди виконавець залишається читабельно позначеним у старих замовленнях та історії, але недоступний для нового призначення.
- [x] Перепризначення не змінює ціни, кількість робіт, статуси або дати саме по собі.
- [x] Успішна зміна виконавця додає одну подію «Було / Стало»; повторне збереження того самого призначення не створює зайвих подій.
- [x] Нові події історії містять перевірені сервером ідентифікатор і читабельне ім’я автора; їх не можна підмінити полями форми.
- [x] Зміна замовлення та запис історії зберігаються однією транзакцією. Помилка не залишає часткового перепризначення.
- [x] Наявна перевірка ревізії захищає від перезапису зі старої форми, включно з одночасним редагуванням призначення, робіт і статусу.
- [x] Минулі події не отримують вигаданого автора; історичні імена залишаються зрозумілими після перейменування або видалення учасника.
- [x] Список, картка, дошка та друк оновлюються після збереження; незбережена форма не видається за новий збережений документ.
- [x] Тести перевіряють перепризначення, перше призначення старому замовленню, видалення учасника, конфлікт ревізії, відкат транзакції, автора події, повторне відкриття бази та читабельність історії в UI.
