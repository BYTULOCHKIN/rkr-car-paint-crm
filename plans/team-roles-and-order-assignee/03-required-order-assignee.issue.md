# Обов’язковий виконавець нового замовлення

Тип: AFK. User stories: 10–13, 15–16.
PRD: [Команда, ролі та виконавець замовлення](../team-roles-and-order-assignee.prd.md).

## What to build

Під час прямого створення замовлення або взяття заявки в роботу адміністратор
обирає одного активного учасника поточної автомалярки. Ним може бути як
виконавець, так і адміністратор. Без цього вибору нове замовлення не зберігається.
Після збереження виконавця видно у списку, картці замовлення, на дошці робіт
та у друкованому документі.

Це завершений шлях: вибрати учасника → створити або конвертувати замовлення →
повторно відкрити його й отримати друк із правильним виконавцем. Призначення
не змінює цін, складу робіт або доступності замовлення іншим учасникам.

## Acceptance criteria

- [ ] Форма використовує спільні компоненти полів і показує обов’язковий вибір одного виконавця з пошуком за читабельним ім’ям.
- [ ] Для прямого створення та конвертації заявки діють однакові правила призначення.
- [ ] До вибору доступні всі активні учасники поточної автомалярки, включно з адміністратором. Запрошення в очікуванні відсутні в списку.
- [ ] Порожнє призначення нового замовлення відхиляється і формою, і сервером; обійти перевірку прямим викликом неможливо.
- [ ] Сервер повторно перевіряє учасника при збереженні. Видалений учасник або учасник іншої організації відхиляється, навіть якщо значення раніше було в UI.
- [ ] Збереження містить ідентифікатор і читабельне ім’я виконавця, визначене сервером, а не довільний підпис із форми.
- [ ] Виконавця видно у списку, картці, на дошці та у друці; призначення зберігається після повторного відкриття бази.
- [ ] Створення замовлення та конвертація заявки лишаються атомарними: помилка призначення не створює замовлення й не змінює статус заявки.
- [ ] Міграція зберігає старі замовлення без автоматичного призначення. Вони відображаються як «Не призначено» та залишаються читабельними й доступними для друку.
- [ ] Призначення не перераховує суми, не змінює схему кузова й не обмежує видимість замовлення лише призначеним учасником.
- [ ] Тести охоплюють обидві форми створення, обидві ролі призначеного учасника, порожнє й підроблене значення, видалення учасника до збереження, міграцію, повторне відкриття й UI друку.
